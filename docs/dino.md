# 恐龍跑酷（彩蛋）—— 為什麼是自己寫的

按 `g` 叫出來，`Esc` 回到 dashboard。這份文件記錄「先找現成的、找不到才自己寫」
這個決定的依據，以及最後有沒有用到任何第三方程式碼。

**結論：沒有使用任何第三方程式碼。剪影是照 Chromium 的 T-Rex 像素畫一塊一塊抓下來的，所以保留 Chromium 的 BSD-3-Clause 聲明（見文末「素材來源與授權」與 `THIRD_PARTY_NOTICES.md`）。**
下面是找過什麼、為什麼都不適合。

crates.io 上以 `dino`、`chrome dino` 搜尋，唯一的終端機遊戲就是 `terminal-dino`
（v0.2.0，1474 次下載）。**沒有任何 ratatui 版本，也沒有任何以 library 形式
發佈、可以嵌進別的 TUI 的版本。**

## terminal-dino 為什麼不適合 reuse

它是唯一認真的候選：MIT、269 行、只依賴 crossterm 與 rand。但它的架構跟
sysview 幾乎沒有交集：

* **renderer 不相容**：`render.rs` 用 crossterm 直接對終端機下游標指令。
  sysview 全部經過 ratatui 的 `Buffer`，才能保證不畫出面板外、
  跟主題一致、而且可以在測試裡逐格檢查。
* **主迴圈不相容**：`main.rs` 是 `while game.update() { … thread::sleep(TICK) }`。
  sysview 的迴圈是事件驅動的，輸入優先，而且會計算下一個到期時間才睡。
  照搬會讓整個 TUI 在遊戲期間停止回應。
* **玩法不完整**：沒有蹲下、沒有重來、沒有 game over 畫面（`println!` 之後
  直接結束程式）、沒有 resize 處理、場地寬度寫死 100。
* **剩下的可重用部分**：把上面三項換掉之後，真正能留下的是
  「障礙物往左移、碰到就結束、每 4 格加一分」這幾十行算術。

為了那幾十行背上 attribution 與版本追蹤的義務不划算，而且改寫過的東西也
不該掛別人的名字。所以 `src/ui/dino.rs` 是重寫的，只在概念上參考公開的
Chrome dino 玩法（跳 / 蹲 / 隨機障礙 / 速度隨分數上升）。

## 這個彩蛋碰到什麼

刻意列出來，因為彩蛋最容易變成安全或效能的破口：

* 不碰 `sysview-priv`、不需要 sudo、不做任何提權
* 不讀 `/proc`、不讀任何檔案、不寫任何檔案（最佳分數只放在記憶體裡）
* 不連網路、不 spawn 行程、不開 shell
* 不改變 collector 的取樣頻率（有測試在守）
* 遊戲關著時 `App::next_game_tick_in` 回傳一小時 —— 主迴圈一次都不會為它醒來
* 亂數是 8 行的 xorshift64，種子取自開機以來的奈秒數。彩蛋不需要 CSPRNG，
  也不需要為它多一個相依

## 行為對照 Chromium 官方實作

數值不是憑感覺調的，也不是抄部落格上「500 分出現翼龍」那類傳聞。
來源是 Chromium 目前的原始碼：

`https://chromium.googlesource.com/chromium/src/+/main/components/neterror/resources/dino_game/`
（`offline.ts` 的預設 config、`trex.ts` 的 `normalJumpConfig`、
`offline_sprite_definitions.ts` 的 obstacleTypes、`obstacle.ts` 的 `getGap`、
`distance_meter.ts` 的 `COEFFICIENT`、`night_mode.ts`）。
**沒有複製任何一行程式碼**，拿的是行為；剪影則是照它的像素畫一塊一塊抓下來的（見文末「素材來源與授權」）。

### 換算方式

只有兩個常數：Chrome 的像素畫本來就是 2×2 px 一塊，T-Rex 是 44×47 px
= 22×23.5 塊。剪影**照塊抓下來**，一塊對一個 braille 點，最後半塊算一整塊，
所以是 22×24，`PX_X = 22/44 = 0.5`、`PX_Y = 24/47`。沒有縮放、沒有自己補洞。
長度一律照這個比例換算，所以「仙人掌相對恐龍多高」「翼龍飛多高」跟原版一樣。
場地高度也照原版的 150/47 = 3.19 個恐龍高（19 列）。

速度與距離**直接用 Chrome 的單位**（px/frame、px），這樣間距公式、
群組門檻、翼龍解鎖速度、分數換算都能原封不動照抄。

### 刻意不一樣的地方

* **間距下限**：加了「至少一次跳躍的水平距離 ×1.15」。Chrome 的公式允許
  間距小於一次跳躍，玩家得提早起跳 —— 在 600 px 的畫布上那是可以練的。
  我們一格是 5 個子像素（約 0.3 個恐龍寬），時間顆粒度粗得多，同樣的間距
  會變成 frame-perfect 才過得去。有一個測試會前瞻搜尋每一格「跳 / 蹲 /
  不動」，做不出解就算生成器有問題。
* **60 fps，塞住時降到 30**：早期是 33 fps，理由是「每一格移動多少」跟原版
  同量級。但 33 不整除 60：在 60 Hz 的螢幕上一格畫面有時停一個更新週期、
  有時停兩個，這種忽快忽慢比低幀率還容易看出來（judder）——使用者說的
  「偏卡」。60 fps 跟原版一樣每格移動畫布寬的 1%。代價：位元組約兩倍、
  CPU 多約兩個百分點。實測（190×48 真 PTY、看畫面自己跳的 autopilot、30 s，
  `-i 1.0 / 0.5 / 0.2` 三種）：57.5 fps、幀間隔中位 17.5 ms、p99 17.7–18.8、
  最大 21 ms、**0 次超過 45 ms**、46–57 KB/s；CPU 2.85%（沒玩 1.05%）。
  33 fps 的版本是中位 30.6、最大 38.9 ms —— 那個最大值就是每秒一次等行程
  掃描（見下）。`terminal.draw` 裡的 flush 是阻塞的：
  終端機或 ssh 消化不了時 write 會卡住，連輸入都讀不到；所以量每一格的
  flush 時間，超過一格就把接下來一秒的畫格拉長一倍（30 fps，正好一半、
  仍然對齊），追上了就恢復（`main.rs` 的 `Pacer`）。
  另外行程掃描（`/proc`，量到 4–5 ms、行程越多越久）原本在主執行緒上，
  每一秒有一格畫面要等它 —— 現在在背景執行緒上掃，主執行緒只收結果。
* **跑道 130 欄而不是 150，恐龍靠左**：要跟 Chrome 完全一樣的反應時間
  （1.41 s）需要 150 欄 —— 那是整個終端機的寬度，不再是「中間浮一塊」。
  130 欄、恐龍站在 x=10（Chrome 是 50/600 ≈ 8%，這裡 4%）給 1.27 秒；
  同一條跑道恐龍站在 x=26 時是 1.18 秒，早期 72 欄只有 0.84 秒，障礙物
  一出現就在眼前。
* **蹲下**：Chrome 用 keydown/keyup 控制蹲多久。終端機**收不到放開鍵**
  （實測 crossterm 在這裡只送 `Press`，沒有 `Release` 也沒有 `Repeat`），
  所以改成「按一下蹲 400 毫秒，再按就延長」。按住時鍵盤自動重複會一直
  延長，點一下也蹲得夠久看得見。蹲姿的剪影也**錨在後面**：Chrome 的蹲姿
  59 px 寬、畫在同一個 x，頭往前伸 15 px、碰撞箱跟著往前 —— 蹲下反而更
  容易撞到。這裡把蹲姿的前緣對齊站姿的前緣（往後長，不往前），碰撞箱的
  前緣不變。
* **死掉之後**：`r` / Enter 立刻重來，跳躍鍵要過 750 ms 緩衝（跟 Chrome
  一樣），**其他鍵一律無效**。早期版本是「除了 Esc 之外任何鍵都重來」，
  於是提示上寫的 `r 重來` 毫無意義。提示列在死掉時也會換成
  「r 重來 · Esc 關閉」—— 那時跳與蹲都沒有作用，就不該寫在上面。
* **日夜只翻轉遊戲畫布**，不動 sysview 的主題。單色終端用反白表示。

## 亂數

正式遊玩的種子取自 `std::collections::hash_map::RandomState` —— 標準庫用它
防雜湊碰撞攻擊，每個行程的值由作業系統的亂數來源決定。這樣不必為了一個
彩蛋多一個相依，也不必自己開 `/dev/urandom`（這個模組不碰檔案）。
**不能用時間當種子**：同一秒內開兩局會拿到同一串障礙物。

測試用 `Dino::with_rng(now, best, Rng::from_seed(n))` 注入固定種子，
所以「同種子同序列、不同種子不同序列」是可以斷言的。

## 呈現：浮在儀表板上的一塊，不是另一個分頁

第一版整頁接管：遊戲開起來整個 dashboard 消失。那看起來像切到另一個
View，而不是「在儀表板上面開了一局」。現在跟說明頁、Explain 用同一套
overlay 外框（`ui::widgets::modal`），中間浮一塊遊戲窗，背景的監控資料留著。

**renderer 選 braille，不是四分格。** 四分格是吉祥物用的，因為剪影要
crisp；這裡最重要的是動起來順不順，而 braille 每格 2×4 點，橫向解析度
跟四分格一樣、縱向是兩倍。第一版用整格的方塊字（`█▐▌`）當像素，
一個「像素」就是一個字元格，所以又粗又大，也做不出跳躍的中間位置。

剪影**照 Chrome 的原圖一塊一塊抓下來**（站 22×24 塊 = 11×6 格；蹲 29×13 塊）：
方頭、上面兩角各缺一塊、一格白的眼睛、下顎缺口、尾巴翹在左上、尾巴與脖子
之間背部的凹陷、小手、兩條腿、跑步兩格換腳（抬起的那隻腳縮短、腳掌往前）、
蹲下的長扁身（頭跟背同高，像鱷魚）、撞到時眼睛變大一圈中間一點。抓法是把
參考圖還原成方塊格 —— 逐欄量暗色區段、換算成塊 —— 不是看著畫。之前自己
照比例畫的 16×20、22×23 版本背部被抹平、尾巴併進身體，使用者一眼就看出來了。

## 為什麼是 modal 而不是嵌在頁面底部

考慮過兩種：整頁 modal（跟 Help / Explain 一樣），或是接在目前頁面下方、
讓整頁變成可捲動的長文件。選了 modal：

* **輸入歸屬乾淨**：遊戲開著時所有按鍵都屬於遊戲。docked 版本必須決定
  「空白鍵是跳還是暫停取樣」，而那個決定不管怎麼選都會有人按錯。
* **任何時候都叫得出來**：不必先確認目前頁面有沒有空位。
* **不動到既有架構**：docked 版本要把每一頁都改成可捲動的 viewport，
  焦點系統、resize、每一頁的版面都要跟著改。為了一個彩蛋改動整個
  dashboard 的排版模型，代價完全不成比例。
* **效能**：modal 期間底下的 dashboard 完全不畫（collector 照常取樣），
  所以每格遊戲畫面只送出遊戲那幾十格的差異。

docked 版本作為未來想法保留，但這一版不做。

## 排行榜（這台機器所有人共用）

死掉之後場地上會浮一塊：**這台機器所有人的前五名**、還有（如果你進得了榜）
一個填名字的框。

### 規則

* 分數**嚴格大於**第五名（或榜上還不到五筆）才會問名字。0 分不問。
* **同名取最高**：榜上已經有這個名字而且比你高（或一樣高），這次不記，
  畫面會說「榜上的 X 已有 NNNNN，這次沒有更高，不記錄」；比你低就蓋掉。
* **不填就不記**：Esc 或空白的 Enter 都不會留下任何東西。
* 每筆顯示 `名字  分數  @帳號`——帳號是**檔的 owner**，跟名字一樣就不重複寫。

### 存在哪裡、誰能寫

| | |
|---|---|
| 共用目錄 | `/var/lib/sysview/dino`，`1777`（sticky，跟 `/tmp` 一樣）。由 `make install` 建；**sysview 自己不會建**（要 root） |
| 每個人 | 只寫自己的 `<uid>.json`（0644，先寫暫存檔再 rename）。別人的檔只讀、動不了 |
| 沒有共用目錄 | 退回 `$XDG_DATA_HOME/sysview/dino-scores.json`（私人榜），標題會說「只有你（共用榜未啟用）」 |
| 換位置 | `SYSVIEW_DINO_SCORES=/some/dir`（要存在、要能寫） |

### 這是遊戲的榜，不是身分或稽核資料

分數是在你自己的行程裡算出來的：sysview 能寫的，你用編輯器也能寫。真正的
防作弊要把算分數的程式放在使用者動不了的權限下（setgid 的遊戲、daemon），
這個專案明文不做這種事。所以這裡做的是「讓作弊看得見」：

* **帳號**（無法偽造）：檔的 owner 是 kernel 記的。你可以在自己的檔裡寫別人
  的名字，榜上會顯示是從你的帳號來的。
* **標籤**（嚇阻）：每筆帶一個 keyed hash（SipHash-2-4，綁 uid、名字、分數、
  時間）。用編輯器改過的紀錄標籤對不上，**靜默丟掉**——不排名、不顯示、
  不計數，改的人不會得到任何提示。金鑰在 `src/scoreboard.rs` 裡，找到的人
  算得出合法標籤；旁邊留了一句話給他。

別人的檔一律當不可信輸入：只讀一般檔（不跟 symlink、不碰 FIFO）、檔名的
uid 必須等於檔的 owner（先搶建別人的檔名塞假資料不算數）、64 KB 上限、
JSON 壞了整個跳過、名字清掉控制字元並截到 12 格寬。
